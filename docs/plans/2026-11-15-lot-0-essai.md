# Lot 0 : essai jetable — plan

> **Pour les agents qui exécutent :** sous-skill requis : superpowers:executing-plans, tâche par tâche, **dans l'ordre et sans parallélisme** (le plafond de deux sessions d'essai doit rester maîtrisé). Les étapes utilisent des cases à cocher (`- [ ]`).

**But :** vérifier sur Claude Code les hypothèses dont dépend le design, avant d'écrire une ligne du produit.

**Architecture :** de petits scripts Node.js (lancement, liste des sessions, attente, sondes de barre d'état, hooks, lecture de transcript) branchés sur des sessions d'essai par `--settings`, isolées de la configuration de l'utilisateur. Les sessions tournent dans un bac à sable hors de tout projet. Chaque expérience note son résultat, sa preuve et sa conséquence dans `docs/spike-results.md`.

**Outils :** Node.js 18+, Claude Code (version notée au début), Docker (Linux).

**Spec :** [`docs/specs/2026-11-14-relaylead-design.md`](../specs/2026-11-14-relaylead-design.md), section « À prouver d'abord ».

## Contraintes globales

- Scripts en Node.js sans dépendance, dans `spike/` (gardés pour rejouer l'essai) ; sorties dans `spike/out/` (ignoré par git). Aucun recours à `jq`, `uuidgen` ou `sleep` dans les consignes données aux sessions : `node spike/wait.js <secondes>` (moins de 100 s) à la place de `sleep`.
- Bac à sable : `~/relaylead-sandbox` (dépôt git jouet), hors des dossiers de projets de l'utilisateur et de tout dossier surveillé par un autre orchestrateur.
- **Lancement isolé par défaut** : toute session d'essai passe par `spike/launch.js`, qui ajoute `--setting-sources project,local --strict-mcp-config --settings <fichier>` et le mode `--permission-mode acceptEdits --allowedTools "Bash(node *)" Read Write Edit`. Le mode sans autorisations n'est utilisé que là où une tâche le demande explicitement. Une seule variante (Tâche 3) tourne avec la configuration de l'utilisateur, pour mesurer l'interférence.
- Sessions nommées `rl-…`, modèle `haiku` sauf mention contraire, **deux au plus en même temps**, et seulement si la charge (`os.loadavg()[0]`) est sous le nombre de cœurs.
- Aucune écriture dans `~/.claude/`. Chemin absolu des sorties transmis par `RL_OUT`.
- Une expérience qui échoue n'est pas contournée : on note l'échec, la cause observée et le repli de la spec.
- **Points bloquants** : 1, 3, 4, 8, réveil (Tâche 4) et Linux (Tâche 8). La partie Windows du point 9 est reportée au lot 4 par décision de l'auteur (15 nov. 2026), la CI multiplateforme du lot 1 couvrant le cœur et les hooks avec le faux agent.

## Points d'attention

1. **Interférence de la configuration de l'utilisateur** (plugins, MCP, hooks, mode `auto`) : elle peut faire réussir ou échouer une expérience pour une mauvaise raison. → Isolation par défaut ; une variante non isolée mesurée à part (Tâche 3, étape 4).
2. **Un `claude attach` ou `logs` pendant une mesure** peut déclencher la barre d'état et créer un faux positif. → Aucune de ces commandes pendant les tâches 3 et 4.
3. **Le dossier des transcripts** est dérivé du dossier courant de façon non documentée ; les sous-agents écrivent dans `<session>/subagents/`. → Recherche par identifiant de session ; calcul sur le fichier principal seulement, testé sur un vrai transcript (Tâche 1).
4. **Sessions, transcripts, conteneurs et jetons oubliés.** → Nettoyage vérifié par des commandes qui doivent renvoyer 0 (Tâche 9).
5. **Ambiguïté des noms** (`x/lead/1` contre `x/lead/10`) et commandes qui n'acceptent que l'identifiant court. → Tout arrêt et toute suppression passent par l'identifiant résolu par `spike/sessions.js` (Tâche 2).

### Tâche 1 : bac à sable et scripts

**Fichiers :**
- Créer : `spike/lib.js`, `spike/launch.js`, `spike/sessions.js`, `spike/wait.js`, `spike/statusline-probe.js`, `spike/mailbox-hook.js`, `spike/stop-hook.js`, `spike/permission-hook.js`, `spike/pretool-hook.js`, `spike/settings/*.json`, `spike/lib.test.js`, `.gitignore`, `docs/spike-results.md`

**Interfaces :**
- `spike/lib.js` :
  - `findTranscript(sessionId: string): string | null` : `~/.claude/projects/*/<sessionId>.jsonl`.
  - `contextTokens(transcriptPath: string): { tokens: number, model: string, at: string } | null` : dernière ligne `type: "assistant"` du fichier principal ; `tokens = input_tokens + cache_read_input_tokens + cache_creation_input_tokens`.
  - `writeJson(path, value)` (atomique), `readStdinJson(): Promise<object>`.
- `spike/sessions.js` : `listSessions({ all?: boolean, cwd?: string }): Array<{ id, sessionId, name, state, status, waitingFor, pid }>` (lit `claude agents --json`) ; en ligne de commande : `node spike/sessions.js [--all]` affiche la table ; `node spike/sessions.js stop <nom exact>` et `rm <nom exact>` résolvent l'identifiant court et affichent le code de retour.
- `spike/launch.js` : `node spike/launch.js --name <nom> --settings <fichier> [--model haiku] [--mode isolated|user|bypass|manual] [--session-id auto|none] [--agents <json>] [--agent <nom>] -- "<consigne>"` ; lance `claude --bg` dans le bac à sable avec les options d'isolation, affiche `{ name, sessionId, shortId, sessionIdHonored }` : `sessionIdHonored` vaut faux si l'identifiant réel (lu dans la sortie puis dans `claude agents --json`) diffère de celui demandé.
- `spike/wait.js <s>` : attend s secondes (au plus 99).
- Sondes :
  - `statusline-probe.js` : écrit `RL_OUT/statusline/<session_id>.json` = `{ at, context_window, rate_limits, model, env: process.env.RL_MISSION }`.
  - `mailbox-hook.js` (`PostToolUse`) : livre `RL_OUT/mailbox/<session_id>/*.md` en `additionalContext`, déplace dans `read/`.
  - `stop-hook.js` (`Stop`) : s'il reste du courrier non lu, bloque la fin de tour avec la raison « Message de Relaylead : <contenu> » et le déplace dans `read/`.
  - `permission-hook.js` (`PermissionRequest`) : **liste blanche** : autorise seulement `node spike/*`, `git status`, `git add`, `git commit` ; refuse tout le reste avec « Refusé par Relaylead : une question a été créée pour l'humain. Continue avec le reste de la tâche. » et écrit `RL_OUT/questions/<horodatage>.json`.
  - `pretool-hook.js` (`PreToolUse`) : refuse toute commande ou tout chemin contenant `rl-forbidden` avec le même message ; laisse passer le reste.
